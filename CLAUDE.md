- **PHYSICAL FLOORS CRASH LOUD; the C STACK IS NOT ONE — overflow is IMPOSSIBLE BY CONSTRUCTION, never caught.** Disk and RAM are the genuine physical limits of the unbounded BFS; the C stack is made a NON-limit by trampolining every call and self-hosting every re-entrant. ALL calls trampoline onto the HEAP stack so any flow is heap-switchable at ANY call depth: the OP_call/return trampoline (quickjs.c `TrampFrame`/`do_tramp_call`/`do_return` + exception unwind) pushes every `OP_call`/`OP_call_method`/tail-call onto a HEAP frame and `goto restart`s instead of recursing into `JS_CallInternal`, so the C stack stays flat and direct/method/tail recursion is unbounded — the substrate for snapshot/preempt/evict/replay at depth. Deep preemption fires at ANY tramp depth: `FLOW_YIELD_CHECK` (gated by `flow_base_activation` so only the base activation unwinds the C stack, never a nested C-recursive one) stashes the whole `tf_top` heap chain into `JSAsyncFunctionState.tramp_top` and unwinds the base activation off the C stack; the generator-resume path reconstructs the top frame and `goto restart`s at its saved pc/sp; `free_tramp_chain` evicts a deep-suspended flow (mirrors `do_return`'s per-frame teardown). Two competing deep flows preempt each other mid-descent (`@RESULT._switches` counts the interleaves), both return the byte-exact reference value with frames intact, and under a host quantum both evict via `free_tramp_chain` then park as replay recipes — fairness and cross-session resume hold at ANY depth, not just the flow base. C-function re-entry (a C builtin calling `JS_Call`→`JS_CallInternal`) reaches the SAME no-C-recursion outcome by TWO mechanisms split by whether the builtin holds a C continuation. **CALL-SITE-RESOLVED** re-entrants (`.bind`/`.call`/`.apply`/`Reflect.apply`, the `f(...args)`/`OP_apply` call-spread, and every CALL / READ / WRITE / MEMBERSHIP / DELETE THROUGH a Proxy) hold NO surviving continuation — a proxy trap is a SINGLE handler dispatch whose only post-work is placing the ONE result via the `(call_first,call_argc)` stack-shape descriptor `do_return` reads (PUSH-1 for a value-producing trap get/has/delete; PUSH-0 `discard_result` for `set`, an assignment leaving nothing on the stack — the compiler emits `OP_dup` before the put when the value is needed) plus freeing the handler method + arg array (the OWNED method on `TrampFrame.owned_func`/`owned`) — so the interpreter RESOLVES them AT THE OPERATOR SITE and trampolines the ultimate target directly, no C round-trip: `js_tramp_forward_setup` unwraps the `.bind` chain / `.call`+`.apply` reslice / spread `build_arg_list` to the ultimate NORMAL target (spliced args copied into the callee frame, innermost bind's `this` winning); `js_tramp_proxy_setup`/`_get_setup`/`_prop2_setup`/`_set_setup` re-dispatch the NORMAL handler — `apply(target,this,[args])` at `OP_call`, `get(target,key,receiver)` at `OP_get_array_el`/`OP_get_field`, `has(target,key)` at `OP_in`, `deleteProperty(target,key)` at `OP_delete`, `set(target,key,value,receiver)` at `OP_put_field`/`OP_put_array_el`, `this=handler` — or forward to the proxy's target when the trap is absent. So recursion is unbounded THROUGH a bound/`.call`/`.apply`/spread/proxy reference. The obscure `[[Get]]` frozen-property and `[[Set]]` strict-mode-throw invariants are documented DEVIATIONS (the trap's writes/fetches/taint all still happen; a spec-violating trap result is pathological and any phantom past it is WFQ-starved, never a real endpoint). **CONTINUATION-HOLDING** re-entrants (array iteration `forEach`/`map`/`reduce`/`sort`-comparator, `String.replace`/`JSON.stringify` callbacks) keep loop/accumulator state ON the C stack between callback invocations, so they CANNOT be call-site-unwrapped; they reach no-C-recursion by being SELF-HOSTED as bytecode (the loop becomes a heap bytecode frame; the callback dispatches via the already-trampolined `OP_call`) — a call-site unwrap of a `forEach` is a category error. `sort` and `JSON.stringify` add ONE rule: where the builtin ITSELF BRANCHES on a value (sort's `cf(...)<=0` order decision; stringify's `typeof`/`Array.isArray` type-dispatch), an OPAQUE operand must NOT fork that branch — short-circuit it via the `__isOpaque` leaf (a concrete bool that never forks), avoiding a WRONG fork-explosion (O(n·log n) for sort). What the short-circuit YIELDS differs by whether the branched-on aspect is MEANINGFUL: sort's element ORDER is meaningless → collapse to 0 (arbitrary but deterministic); stringify's opaque field VALUE is TAINTED external input (flowing to a body/sink) → YIELD THE OPAQUE itself, taint PRESERVED, never a concrete placeholder that would DE-TAINT and drop the @S flow. Either way the builtin STILL runs the callback (trampolined, unbounded, so its emits/side-effects happen); only the meaningless fork is removed. A self-hosted prelude builtin MUST be compiled under `JS_SetBuiltinCompile` (born `executed=1`) so orphan-driving never force-invokes the uncalled builtin with opaque args (sort uniquely proceeds past its guard and fork-explodes there). The trampoline MUST restore the CALLER's closure `var_refs` on return (`caller_var_refs`) — else nested-closure non-tail recursion (a recursive tree-walk helper, ubiquitous) crashes. All this makes `JS_ThrowStackOverflow` impossible on the path; `js_check_stack_overflow` in `js_call_c_function` is DEAD for a re-entrant once its mechanism lands and is deleted then; recursion is reviewed at every depth, never a RangeError — a tree-walk via `children.forEach(walk)` overflows nowhere because the iterator is self-hosted. The per-flow heap+DOM COW DELTA swaps on context-switch (`JS_CowUnapply`/`Apply`/`BufTake`/`Load`/`Free` + `dom_unapply`/`dom_apply`), so a shared-state WRITER (heap OR DOM) is fully preemptible — no `JS_CowDepth` guard, no writer running to completion. Boot IS the first flow: captured as `g_boot_delta` (COW active during the page's inline scripts, mutation + global-CREATION entries incl. `let`/`const`), which a candidate flow UNAPPLIES to a true pre-boot heap and REAPPLIES after. Heap captures are IDENTITY-based: a property mutation records `(obj,atom)` and RE-RESOLVES via `find_own_property` at every unapply/apply/revert — pointer-safe across property-array realloc/compaction/delete (a raw `&pr->u.value` would dangle when the object grows), while closure captures keep their stable `var_ref->pvalue` slot; global `let`/`const` CREATION is captured (`add_property` extends `global_var_obj`). The per-flow DOM delta covers attr + node-insert; node-removal needs no capture (no host removal op exists — `innerHTML` is a sink recorder, not a DOM mutation); boot's DOM writes land in `g_boot_delta` like any flow's, so a source STASHED IN THE DOM by boot or handler A reaches a sink in handler B by the same COW swap that carries heap taint. A loop reuses one frame; deep recursion grows by heap segments — both yield per-opcode. **The DISPOSITION is offensive:** UNTIL a re-entrant's self-hosting lands, its residual C-recursion overflow CRASHES LOUD (findings discarded, `_engineCrashOccurred`), NEVER caught-and-continued into a soft RangeError that masks a bound and builds on an uncertain instance — the fix is ALWAYS to COMPLETE the primitive so overflow cannot happen, never to catch it or cap the depth to look "robust". A crash on a not-yet-self-hosted path is a TODO surfaced loud, never a design; hitting a GENUINE floor (IDB filling up) crashes as OOM — the real resource wall, not a bug.
- **EVERY RUNTIME JOB IS A SCHEDULER FLOW — no job-queue drain; async is UNBOUNDED-until-DISK, kept safe by PAGING (not by a redundancy judgment — you CANNOT tell a path is redundant).** EVERY enqueued job — an async resume, a promise `.then`/`.catch`/`.finally` reaction, `queueMicrotask`, a `setTimeout`/rAF callback — is a FIRST-CLASS FLOW in the one WFQ (COW-snapshot, per-opcode + quantum preemptible, park-as-REPLAY-RECIPE-able), EXACTLY like a sync trampolined flow; Two orthogonal mechanisms keep it safe with NO bound: (1) the WFQ ORDERS by ACTUAL EMITTED output — a level that has SO-FAR emitted nothing is momentarily OUTRANKED by productive flows (breadth extracted first), but it RISES the instant it emits and is NEVER dropped or predicted-useless; (2) RAM pressure EVICTS the lowest-value tail to the IDB cold tier (replay recipe = decision vector; live delta DROPPED §replay-not-serialize) and RESUMES it next session — DISK is the SOLE floor. So the deep tail sits ON DISK, resumable-but-outranked: 'STARVE' means ONLY deprioritize-and-page (resumable, cross-session), NEVER terminate — starve-as-terminate is a banned bound. An async recursion that OOMs is never a missing bound — it is the recursion running in a NON-PARKABLE structure (one shared delta + an unbounded runtime job queue that cannot page to disk); making every continuation a first-class parkable flow keeps it UNBOUNDED-until-disk — the OOM of a non-preemptible drain impossible BY CONSTRUCTION, never caught, never depth-capped, never redundancy-pruned. Context-switch SWAPS deltas (unapply the outgoing flow's writes to restore the baseline, apply the incoming flow's), NOT a serial revert-to-baseline — so EVERY flow is preemptible mid-write (no writer ever "runs to completion") and any number interleave. The delta then holds ONLY genuine cross-flow state — mutations of baseline slots/nodes and creations that extend the shared baseline — never a flow's own transients (the per-iteration `Request`/`Promise`/temporary a loop body builds). This makes the primitive right BY CONSTRUCTION rather than by any cap: a loop doing per-iteration private work has a small delta because that work is flow_local, not because a limiter trims it. **The invariant only holds if EVERY flow runs at flow-private mark, so an iteration over opaque input MUST fork each iteration as its OWN parkable flow** (§EVERY-RUNTIME-JOB) — then each iteration's transients are flow_local and skipped and no single flow inherits another iteration's junk. Boot is the ONE flow whose creations are legitimately BASELINE (they are the shared starting state the frontier layers over), so a loop in boot must not spin in-place either: an opaque loop in boot forks per-iteration boot-flow siblings exactly like any other flow, keeping the boot delta O(what boot genuinely shares). **A delta that is GENUINELY large — a loop mutating real SHARED state each iteration (`state.items.push(x)`, a reactive store update, `cache[k]=v` on a shared object, building shared DOM — COMMON in real code, never assume it is rare) — is O(N) shared writes, and is handled by the ONE resume mechanism (§Cross-session), NEVER by serializing the delta to disk.** There is NO delta-byte paging / buffer-pool spill / "page back on unapply-apply" — that is the live-graph serialization §Cross-session forbids (a delta entry names its target by a live heap pointer with no cross-tier identity; quickjs has no continuation serializer). The RAM bound comes instead from making each iteration its OWN parkable flow (§EVERY-RUNTIME-JOB: an opaque branch's CONTINUATION is a first-class flow — NOT loop-detection, just "continuations are flows"), so a loop is a CHAIN of per-iteration flows, each capturing only ITS iteration's shared writes (O(1) incremental) instead of one flow accumulating O(N). SAME-SESSION and CROSS-SESSION resume are the SAME operation: a hot flow resumes from its (hot) parent cheaply; an evicted one DROPS its live delta and keeps its REPLAY RECIPE (decision vector), replayed from boot on rehydration — hot in memory or cold in IDB, IDENTICALLY. So the hot window is bounded, the cold prefix is recipes on disk, and the full O(N) never sits in RAM at once — with ONE honest exception: a uniformly-PRODUCTIVE unbounded shared-accumulation loop (every iteration BOTH emits new AND mutates shared state) has O(N) genuinely-valuable state the WFQ cannot starve, and it hits the physical RAM→DISK floor — the real limit, faced honestly, never a cap and never dedup'd. Diagnose a large delta by WHAT fills it: flow-private bloat (the loop runs at boot's mark=0 so its transients are WRONGLY captured — fix by running each iteration at flow_local mark, §boot forks per-iteration siblings) or genuine shared state (real BFS work — per-iteration flow chain, recipe-parked, replayed, floor-bounded); measured from the delta, never assumed, and the response is never a cap and never delta serialization.

- **Attention:** per-opcode RETURN-to-scheduler from `JS_CallInternal` — NOT a JSPI suspend (JSPI saves the C stack while frames live on the heap arena → teardown desync/double-free). Universal, boot included. The yield CHECK is per-opcode; there are TWO orthogonal yield DECISIONS at that one check. (1) The VALUE yield — suspend the running flow the moment a parked flow outranks it (or on an emit/fork/suspension that changes ranks), NEVER after N opcodes (a per-N/opcode-budget counter is a step cap, banned); a flow that stays top-ranked runs on with ~zero switch cost; the WFQ, not a clock, decides WHICH flow runs. (2) The COOPERATIVE-QUANTUM yield — orthogonal and about THREAD-SHARING, not value: when the running flow has held the ONE worker thread for a bounded wall-clock slice, it suspends (same COW-snapshot suspend path as the value yield) and `scheduler_run` RETURNS to `qjs_step` so the host loop pumps messages / interleaves other engines / streams findings / snapshots, then re-enters and RESUMES THE SAME top flow on the byte-identical frontier. This is REQUIRED and universal (a lone engine has neither a competitor nor RAM pressure, so without it its one `qjs_step` never returns and the worker freezes, unobservable); it is a yield, NOT a cap (§NO BOUNDS) — it truncates nothing, drops/reorders no flow, and never decides what runs. The quantum is checked at BOTH the per-opcode hook (so a long single flow — e.g. trampolined recursion — yields mid-run) AND at `scheduler_run`'s loop head (so it returns to the host rather than re-dispatching the just-expired flow). Driving the call/object graph synchronously outside the scheduler (a boot epilogue) is the same sin as a bound — drive it per-orphan, yielding.
- **THE PROJECT IS BFS + TIME-TRAVEL, EACH CODE FLOW RUN FAIRLY — this is the whole scheduler in one line.** A "code flow" is a path through the program = a DECISION VECTOR over the shared pre-boot baseline; its state is `replay(baseline, decision vector)`, isolated by its per-flow COW delta. BFS: the ONE WFQ runs flows by value-of-information, FAIRLY — no flow monopolises, a deep loop does NOT run to completion depth-first while sibling flows starve; the running flow yields the instant a parked flow outranks it (value) or the quantum expires (thread-sharing). Time-travel: snapshot (COW) → rewind to baseline → replay a decision vector reconstructs ANY flow's state, hot or cold. A large loop is therefore just a lot of FAIR BFS work that is ALWAYS resumable from EITHER tier — there is nothing to bound and nothing to dedup.

ITERATING an opaque COLLECTION (an injected list/config: `state.items.forEach`/`map`/`for-of`, `Object.keys(cfg).forEach`, `for(k in cfg)`, `for(i<items.length)`) FORKS UNBOUNDED like any opaque loop — each iteration a PARKABLE flow driving the body/callback with an opaque element/key, value-ordered + paged to disk (§EVERY-RUNTIME-JOB), NOT 'driven once': predicting iterations 2..N redundant is the banned seen-set — you cannot know a later iteration adds nothing without running it, and shared state can make a byte-identical-input call PROGRESS. The FIRST iteration reaches the per-element endpoint/sink behind the injected state (productive, stays hot); the identical-input tail emits nothing NEW so is immediately OUTRANKED and PAGED (resumable, never pruned) — so it BEHAVES like once WITHOUT being a bound. An opaque `.length` comparison FORKS (continue vs exit) like any opaque branch — it does NOT 'abort': parkable flows page the deep continue-tail to disk (the SAME primitive that keeps async unbounded), the exit-arm continues the program. NEVER fabricate a concrete index/key (never-invent). A method called ON an opaque (its callback arg) is driven as a scheduler FLOW, not synchronously. But the app's OWN same-origin resources are TRUSTED ground truth to be LOADED, never left a shape: a fetch whose body is JAVASCRIPT is ALWAYS fetched + EXECUTED (a lazy chunk/module reveals real endpoints + branches + values — the headline moat surface); a CONFIG / same-origin DATA fetch is ALWAYS loaded so its fields become CONCRETE param examples, while its use in a BRANCH still FORKS / feasible-refines (loading kills the shape WITHOUT collapsing exploration — a loaded `features.admin:false` must NOT concretize the `if(features.admin)` gate, or the admin endpoint the moat wants is lost; config is opaque-for-control-flow yet carries its loaded value as the example, EXACTLY like `location.search`); a reply field flowing into a param drives the bounded `fromReply` GET. All via ONE bounded safe GET per resource, one-per-endpoint cached, origin-scoped creds under safeFetch's SOP/CORS; `location.origin`/`host`/`protocol` (the principal) is CONCRETE for URL building. A SHAPE for any APP-OWNED value is therefore a DRIVING FAILURE — the fix is to LOAD the resource or close the drive (real-instance drive, SSR seed, render-cycle), NEVER to accept `{shape}`; only external attacker input legitimately lacks a real value.
- **Active discovery is REQUIRED** (lazy loaded scripts + discovery docs + Google API `req2proto` error-probes) — passive learning is too thin. Each active fetch is made FROM the document that learned the endpoint, CORS-bounded both ways to the page's own reachable surface, one-per-endpoint (no method is universally safe — GET can mutate via `/logout`, `/delete?id=`), never a blind sweep. Endpoints learned from runtime fetch/XHR hooks INSTEAD of QuickJS mean the core forced-exec is underperforming — fix the driving, don't lean on the hooks. **Static assets are NEVER endpoints** (magic-byte + content-type, not URL suffix) but still drive the code path. A STATE-MUTATING request (POST/PUT/DELETE, or a side-effecting GET like `/logout`, `/delete?id=`) is NEVER fired to learn — no `fromReply`, no probe, because the side effect is REAL — so its example values come ONLY from the local forced-exec path; that server-side-effect surface is the frontier where forced execution must derive the request WITHOUT a real response, never by firing it.
- **Bind before build:** source a missing Web/spec capability host-runtime (JSPI) → engine intrinsic → existing Lexbor module → faithful spec port → hand-roll last (never crypto/parsers from scratch).
