# API Security Researcher — Development Guide
Work autonomously and continuously across all ideas. No mocking, no placeholders, no heuristics, no summaries, no workarounds. Context length is not a stop signal — keep iterating. Tests must cover whats not fixed and they should fail and must be fixed without avoidance. No side ledgers or coverage files — the code + this guide are the only record.

## Project Overview

A Chrome Extension (MV3) for API discovery, protocol reverse-engineering (Protobuf/JSPB/JSON/gRPC-Web/GraphQL/SSE/NDJSON), JavaScript security code review, and security testing across all websites.

The analyzer's core is **forced multi-path execution on a forked QuickJS engine compiled to WebAssembly**, not a hand-coded interpreter. Re-implementing ECMA semantics on Babel (`extension/lib/ast.js`, now **deleted**) was a runtime-on-Babel dead end — an unbounded transfer-rule treadmill that could never match a real engine, which is why minified jQuery's `$.ajax`→transport never resolved. (V8 was evaluated and dropped: no first-class wasm target, and `jitless` negates its JIT edge, so a real engine with a tiny, portable patch surface — QuickJS-ng — was the correct choice.) The unmodified bundle is *executed for real* by patched QuickJS inside the extension's offscreen Web Worker; only the **host/environment boundary** is modelled, never the language. The boundary is two layers: `engine/qjs/qjs_dom.c` binds **Lexbor** (spec HTML5 parser + DOM + CSS selectors + WHATWG `URL`, compiled into the same wasm) so `document`/elements/`customElements`/`new URL()` are a real spec DOM, not stubs; `engine/qjs/hostedge.js` is the record-only Web-boundary shim (`XMLHttpRequest`/`fetch`/`eval`/`location`/storage/`MessageChannel`/…). XSS taint tracing and API learning share that one execution — no duplicate traversals, no parallel resolvers. `extension/lib/sourcemap.js` (sourcemap + TS-type extraction) is the only remaining genuinely-static helper. No shape matching on identifier names, no heuristic name lists; legacy code is deleted, not wrapped.

**Real interactive testing only — never fake the browser.** Use the live Chrome harness (`testing/harness.js`) over CDP for every UI / popup / SW behaviour check. Never spin up JSDOM, never stub `chrome.*` APIs, never mock the service worker. If a harness command is missing for a check the reviewer needs, extend the harness — don't write a Node-side fake. Tests that bake in synthetic Chrome behaviour codify a fiction; the only ground truth is the real extension running in a real Chrome you should start it via the harness. Extension must be realistically usable with decent performance and high quility.

## Ideas for what to do during continuous work

Don't stay in one idea because it's easier.

1. **Schema learning** — map request/response schemas and URL params from observed traffic + AST call sites. Every field gets a real example value, never a default.
2. **Usable example values** — pull real captured values for every param/field; no synthesized defaults.
3. **Security issue detection** — AST-traced taint from known sources to known sinks. No name matching, no regex — only scope-resolved analysis.
4. **Service grouping quality** — group methods under the right host/path prefix. No cross-origin misattribution from concat tricks.
5. **API vs static asset classification** — magic-byte sniffing + content-type. No URL-suffix heuristics.
6. **Exploit probe** — prove execution end-to-end: NOT REPRODUCED / TAINT REACH ONLY / REAL EXPLOIT. Active payloads (img onerror) set a per-marker flag the probe checks via chrome.scripting.
7. **Real server interaction** — send learned requests through the active page (credentialed) via `schema.verify`, diff response against learned schema.
8. **Website JS review** — follow each finding back to the original JS (sourcemap-resolved). Every per-hop code snippet is captured at analysis time.
9. **Verifying & reviewing output quality** — findings are re-read against real JS; schema.review shows every leaf's example + provenance.
10. **UI review** — the popup and viewer render the same taint-path and tree-shake the reviewer would want; both inspected end-to-end with the harness before claims are made.
11. **Per-finding drill-down** — `finding`, `finding.func`, `finding.callers`, `finding.view`, `finding.exploit` together produce enough context that no guesses are needed.
12. **Harness reviewer context** — every harness command gives ground-truth AST data, not summaries: source snippets per hop, dim transitions, sanitizer report, preconditions, receiver type.
13. **Performance on real sites** — measure on a real 5 MB+ bundle. No change ships with regression > 10 % vs the previous real-site baseline.
14. **Facts not guesses** — every value the analyzer emits is traced structurally. No hardcoded strings, no depth caps, no magic numbers that paper over resolver gaps.
15. **Tooling context improvement** — when a review needed a manual step, the harness learns that step (hop snippets, receiverType, finding.view, etc.).

**Computed values are resolved by RUNNING the code on the real engine — no hand-coded value resolver.** Every URL part, header, body field, and call-site argument is whatever patched QuickJS computes when the unmodified bundle executes under forced multi-path exploration. Closures, prototype chains, `Function.prototype.call/apply/bind`, `for..in`, `Object.assign`/spread, getters, framework state machines (jQuery `$.extend`/`ajaxTransport`/Deferred) all evaluate with exact ECMA semantics for free, because it is a real engine, not a model. WHATWG `URL` is *not* ECMA — it is bound to Lexbor's spec `url` module in `qjs_dom.c` (parse/relative-resolution/components/`searchParams`/setters/`canParse`), so it is spec-exact without a hand-rolled parser. If a value doesn't resolve, the bug is in the forced-execution driver (a branch not explored, a host stub returning the wrong shape, an opaque value not made infectious) — fix the controller/host-edge, never fall back to placeholders, never call a value "dynamic" as if that excuses a gap.

**Always read real website JavaScript — never guess.** Before claiming a fix or a finding is correct, open the actual minified bundle in `globalStore.scriptCache` (or via `finding.view` / `finding.func` / `finding.callers` / `ast.probe.finding`) and confirm the AST decision against the real source. No assumed shapes, no "probably the framework does X", no test-only validation. If a real-site bundle is needed and not yet captured, capture it via the harness; don't reason without evidence.
Production code if traced following ECMA will contain everything it has to otherwise the page would not function.

**Explore real-site APIs end-to-end through the extension UI.** Static AST analysis tells you *what could happen*; the extension's job is to learn *how the API actually works in the wild* by combining (a) reading real JS via the AST pipeline to discover endpoints + schemas + auth shape + value constraints, (b) capturing real network traffic that flows when the user (or harness-driven popup) interacts with the page, (c) calling those learned methods back through the active page (credentialed) via `schema.verify` / popup `Send` and diffing real responses against the learned schema. The popup is the integration surface: when behaviour is unclear, drive the popup with the harness (`popup.select`, `popup.fill`, `popup.send`, `popup.response`) against the real site and read the JS hops that produced any surprise. Synthetic test inputs never substitute for the real-site loop; a learned method is "real" only after it has been replayed credentialed through the page and the response shape confirmed.

**Context the engine handles natively.** Scope chains, inter-procedural arg flow through wrappers, constructor `this.X` chains, `Function.prototype.call/apply/bind`, `for..in`, `Object.assign`/spread/`defineProperty` getters, `encodeURIComponent`/JSON, value constraints from `switch`/`includes`/equality — all of it is just real QuickJS execution, not a feature list to implement. Spec **Web** APIs that are *not* ECMA (DOM, `customElements`, `URL`, CSS selectors) are bound to Lexbor in `qjs_dom.c`, not reimplemented; Web-boundary shims (`btoa`/`TextEncoder`/`crypto`/fetch/XHR) live in `hostedge.js` (see the bind-before-build rule). `lib/sourcemap.js` still extracts interface fields/types from sourcemap'd `.ts` originals to enrich learned param names. A value that is genuinely opaque on every forced path (true attacker input, undecidable computation) is recorded as a param **shape** (name + location + "attacker/opaque"), never invented; a fully-opaque URL/method is a `resolverError`, never a fabricated endpoint (the adapter detects the `[object Object]` opaque marker).

**Forced multi-path execution on forked QuickJS.** The unmodified bundle is executed by patched QuickJS-ng; the patch only changes control-flow handling and adds the opaque domain — the language runs for real. Grounded in named results:

A value opaque on every forced path is a param **shape** (name + location + attacker/opaque), never invented; a fully-opaque URL/method is a `resolverError`. Adding capability = a missing host-edge stub or a missing opaque-infectious transfer (the next rule in `step`-equivalent: an `OP_*` the unknown should flow through) — never a parallel resolver, never re-implementing a language feature.

**Framework code is just JavaScript — RUN it, don't model it.** jQuery `.fail(cb)`, axios interceptors, react-query, redux thunks all bottom out at `fetch`/`XMLHttpRequest`/`WebSocket`/`postMessage`/`eval`/`innerHTML`. QuickJS executes the framework's own bundled implementation exactly; the host hook observes the native call it reaches. No framework recognition, no inter-procedural modelling to get wrong — the engine already did it. Real minified jQuery 3.7.1 (`testing/harness-dumps/jquery-3.7.1.min.js`) is the standing regression gate: jQuery-only (with `driver.js`) must stay `runs=1` / `B=0` (no spurious forks). The full green set, verified native ≡ wasm before any claim: `jq+_role+driver runs=12` (the status-concrete P1: XHR/Response `status`/`statusText`/`ok` concrete, body opaque — without it jQuery's ajax completion forked ~2^14), `_gate runs=6 host_calls=9 endpoints=2`, `_xss @S=4`, `_url`/`_tmpl` polarity. A regression in any is a P1 (the `B=0` invariant caught the `=== sentinel`-through-`OP_CMP` bug that `__isOpaque` fixed).

**Forced-execution engine — the deliverables (the record; no separate ledger).** All under `engine/qjs/` (a forked QuickJS-ng tree) + `engine/build.mjs`:
- `quickjs.c` — patched interpreter: the opaque sentinel + `__opaque`/`__isOpaque` globals; selective forcing in the 4 `OP_if_*`; opaque propagation in `OP_CMP`, `OP_get_field/2`, `OP_get_array_el/2`, `OP_call(_method)`, `js_json_parse`. Patch sites are surgical and source-grounded (read the real handler, single-exit guard mirroring existing idiom).
- `quickjs-forced.h` — the controller: `qjs_forced_decide` (schedule in, `B`/`F` trace out), `qjs_forced_config` (argv config — env is unreliable in modular wasm).
- `qjsmain.c` — host: install the Lexbor DOM binding, eval each file as a global script; parses `--fe-exec/--fe-sched=/--fe-trace=`; surfaces an uncaught bundle throw as a structured stdout `@E {file,message,stack}` (flushed immediately) — a host-model gap, never swallowed.
- `qjs_dom.c` — the QuickJS↔Lexbor binding (the spec DOM/CSS/URL layer): node wrappers with stable identity, `el_of()` node-type guards, real constructors for the full WHATWG HTML element-interface set so `class X extends HTMLElement` works, a `customElements` registry with **live-element upgrade on `createElement`** (a defined element is a real Lexbor node whose ctor ran), `<template>.content` as a live `DocumentFragment`, and WHATWG `URL`/`searchParams` bound to Lexbor's `url` module. No leaked process-lifetime `JSValue` (a never-freed proto dup triggered the `JS_FreeRuntime` GC assert — at emcc `-O1` `assert()` is live so it aborted the worker too).
- `hostedge.js` (single source of truth, drive.mjs tests it) + `driver.js` (event-loop epilogue) — the record-only Web-boundary shim: fetch/XHR/`location`/storage/`MessageChannel`+`MessagePort` (wired into the pump), interim JS base64 + UTF-8 `TextEncoder`/`TextDecoder` (pending the bind-before-build moves).
- `engine/build.mjs` — builds native `qjs.exe` (Node-iterate, via a gcc `@response-file` since ~150 Lexbor TUs blow past the Windows cmd length limit) + three wasm targets (`cli` NODERAWFS, `mod` ES6, `worker` SINGLE_FILE classic-factory) from the SAME patched source, and `stage` copies `qjs_worker.js` + generates `hostedge.gen.js` into `extension/lib/qjs/`. SINGLE_FILE embeds the wasm so the MV3 CSP (`default-src 'none'`) can't block a fetch; `wasm-unsafe-eval` is the only CSP addition. Max wasm memory is the wasm32 ceiling (4 GiB), not emscripten's 2 GB default.
- `extension/ast-thread.js` — the classic Web Worker (run from the offscreen doc `ast-worker.html` per the separate-worker performance architecture): enumerates schedules, one fresh `createQJS()` per schedule, adapts `@H`/`@S` records → `{fetchCallSites, securitySinks, dangerousPatterns, resolverErrors, focusedView, protoEnums:[], protoFieldMaps:[], domEndpoints:[], sourceUrl, sourceMapUrl}` — the exact shape `background.js` already consumes. An `@E` becomes a `resolverError` carrying the **offending `/b.js` source snippet** (sliced from the in-hand combined code at throw time) so a host-model gap is self-diagnosing, not a bare `line:col`. `focusedView` (endpoint/sink spans at real bundle source positions, gate-evidence = example-value spread) is the execution-grounded replacement for the retired Babel viewer index.

**Read the real source — don't generate blind.** Patch sites in `quickjs.c` are edited against the real handler (Read it, match its single-exit idiom). The engine is rebuilt (`node engine/build.mjs native|worker`) and the change is re-verified on real jQuery + the realistic-gate fixture before any claim. Native and every wasm target are built from one source — no test-vs-ship divergence.

**Bind before build — don't reinvent what's vendored.** A missing Web/spec capability is sourced in this strict order, never skipped: (1) **engine intrinsic** already in QuickJS-ng (e.g. `JS_AddIntrinsicAToB` for `btoa`/`atob` — note: wiring it into the *patched* context currently wedges it; that integration is an open bug, not licence to keep reinventing elsewhere); (2) **a Lexbor module already compiled into our wasm** — `url` (done), and the unused-but-present `encoding` (→`TextEncoder`/`TextDecoder`), `css`/`style` (→ real CSSOM / `getComputedStyle`); (3) **one audited single-file** vendored (e.g. a public-domain/BSD SHA for real `crypto.subtle.digest`) — never crypto/parsers written from scratch; (4) **a faithful port of the spec algorithm** (e.g. WHATWG MIME Sniffing for CORB/asset classification); (5) only then hand-roll. The *only* things that are correctly ours: the analyzer-boundary fakes (record-only fetch/XHR/Headers shapes — a real network lib there would be wrong) and the research mechanism (forced-exec controller, opaque domain, event-loop pump, entry-point driver — paper-grounded, no off-the-shelf equivalent). Lexbor is Apache-2.0; QuickJS-ng MIT — both already vetted.

**Structural learning vs. value placeholders.** `fetch("/api/check?nwo=" + encodeURIComponent(repo))` where `repo` is true attacker/opaque input → emit `GET /api/check` with param `{name:"nwo", location:"query", required:true, valueSource:"opaque"}` and NO synthesized value. Structure (path, param names, locations, methods, body field names) is fair game whenever the engine reaches the host call; values come only from what the real execution computed.

**Continuous workflow.** Schema learning, security detection, service grouping, exploit probing, server interaction, JS review, UI review, performance, harness context — all first-class. Never stop, never ask before substantial reversible changes, never surface a limitation as a question; fix it. No workarounds — close gaps without shortcuts.

Tests are for detector polarity (positive + negative). Tests never substitute for real-site verification through the harness.

**Driver-gap ownership.** A host call whose URL/arg has no concrete value on any forced path, where the source shows it WOULD be concrete on a path the driver didn't explore, is a P1: extend the forced-execution decision-vector / entry-point driver / host-edge model to reach it. Don't paper over with placeholders, don't say "unresolvable", don't blame "dynamic".

## Never Do

- **Heuristics after being told no heuristics.** No magic numbers (`bfsDepth: 2`, `MAX_DEPTH = 10`), no name-based matching (`if (callee.name === "fetch")` without scope check), no scoring (A-F grades, confidence percentiles).
- **Placeholders / opaque fallbacks.** No `{foo}`, no `{param0}`, no `"unresolvable"`, no `_describeNode()` string lookups, no returning a partial concat as if complete. Computed values get fully resolved via the existing machinery — or the gap is reported and closed.
- **"unresolvable" / "can't" in code or tests.** The word is a lie; every value has a resolution path the analyzer either has or needs.
- **Ceremonial end-of-turn summaries.** No "tests 748/748 pass, the fix is landed". The diff and the tool output speak for themselves.
- **Stopping because the current micro-task is done.** Rotate ideas; pick up a resolver gap; verify on a new real site.
- **Ignoring timeouts.** A command that hangs past 30 s means the service worker / offscreen worker / harness state is wedged. Inspect `_scriptBuffers`, `_tabMeta`, the offscreen document, the harness lock — find what's blocked. Don't poll-retry, don't raise the timeout.
- **Claim a change works before real-site verification.** Tree-shake line counts, finding reviews, perf numbers — one run is not a claim.
- **Staying in one idea because it's easy.** Security FP cleanup gets addictive; schema / service / UI work gets skipped. Rotate.
- **Synthetic tests standing in for real data.** A polarity test never substitutes for running the change against a real bundle.
- **Preachy or self-congratulating comments.** Comments explain WHY a non-obvious decision was made — never WHAT the code does, never narrate the rule it follows ("// carefully removed the heuristic"). If removing the comment wouldn't confuse a future reader, don't write it.
- **Shipping mocked or placeholder responses.** Every fetched value, every schema example, every fetch-call-site URL is from an observed or fully-resolved source.

## Forced-Execution Analysis Policy

A value is whatever patched QuickJS *computes* when the unmodified bundle runs; a sink/source is what an *executed* call reaches at the host edge, never what it is named. No syntax/identifier matching (code is minified — names are meaningless), no regex on code, no scoring, no heuristics. Scope, prototypes, closures, framework internals are exact because the real engine runs them.

**No caps or depth limits**: 1 MB+ minified bundles must analyse without losing data — no size/step/depth/recursion cap, no schedule/run cap. Termination is structural: (a) schedule enumeration is over *distinct decision prefixes* and each forced run is a terminating program (opaque-gated loops fork → an arm exits); (b) the event-loop pump dedups callbacks by source identity, a monotone bounded set. A hung run is a real bug — a self-re-arming poll not source-deduped, an opaque value reaching a loop that should fork but doesn't, a host stub returning the wrong shape — find it; never add a limit. The host watchdog (a future QuickJS interrupt deadline, analogous to drive.mjs's `timeout:`) bounds wall-time of a wedged wasm instance — that is robustness, NOT an analysis cap.

**Driver/resolver completeness**: every URL/method/body value comes from what the execution computed. A target that is opaque on every forced path is recorded once on `resolverErrors` (the adapter detects the `[object Object]` opaque marker — never a false page-origin URL, never `"unresolvable"`). Closing it is a P1: the missing transfer is either a host-edge stub returning the wrong/concrete shape, or an `OP_*` the opaque should be infectious through but isn't (extend the `quickjs.c` patch set, mirroring the existing single-exit guards) — never a parallel resolver.

- **Network sinks**: `XMLHttpRequest#open/send` and `fetch` are recorded by `hostedge.js` as `@H {api,args,at}` when the *executed* bundle reaches them. `ast-thread.js` pairs open→send PER forced run, aggregates example values across runs; the URL/path/param-name structure is learned even when a value stays opaque (structural learning, never a fabricated value).
- **Inter-procedural / framework**: nothing to model — QuickJS runs the wrapper/factory/HOF/Deferred bundled code itself; the host hook sees the native call it ultimately reaches.
- **Taint sources**: the WHATWG attacker set is the host-edge data made opaque in `hostedge.js` — `location.hash/search`, `document.cookie`, `*Storage.getItem`, `window.name`, `XHR.responseText/response/status`, `fetch` `Response` bodies, `postMessage` event `data`/`origin`. Opaque is infectious (get/call/`JSON.parse`) so it reaches branches and sinks through the bundle's real code. DOM *structure* stays concrete so frameworks boot.
- **Security sinks**: code-exec (`eval`/`Function`/`setTimeout`|`setInterval` string arg), open-redirect (`location.href=`/`assign`/`replace`/`window.location=`/`location.search=`), DOM-HTML (`innerHTML`/`outerHTML`/`insertAdjacentHTML`/`document.write`), and script-bearing `setAttribute` (`href`/`src`/`on*`/`srcdoc`/`formaction`). `hostedge.js` emits an `@S` record **only when the value is tainted** — `__isOpaque(v)` (the non-`OP_CMP` concrete primitive) or the concat-derived `[object Object]` marker. A concrete write (jQuery feature-detection `innerHTML`) is not a finding and costs nothing: polarity proven (4 true positives at exact lines, 0 false positives on the concrete negatives). `ast-thread.js` maps `@S` → `securitySinks{type,sink,source,severity,location:{line,column},taintPath,value}` with `location` in combined-bundle line space (`/b.js`) — what `background.js`'s `_findScriptForLine` expects.
- **Sanitizer-path downgrade**: NOT implemented — severity is category-fixed (`code-exec`→critical, else high). Honest future work; never claim a sanitizer analysis the code lacks.
- **Honest current stubs (the record; close them via bind-before-build, never claim otherwise)**: `crypto.subtle.*` returns empty buffers (a real digest needs a vendored audited single-file SHA — bundles that hash a body get a wrong value until then); `TextEncoder`/`TextDecoder` are interim JS UTF-8 (→ Lexbor `encoding`); `element.style`/`getComputedStyle` are a map stub (→ Lexbor `css`/`style`, already compiled); `structuredClone` is `JSON.parse(JSON.stringify())` (loses Map/Set/Date/cycles). Real-site reach: github boots with **zero `@E`** but its fetches sit behind Catalyst/Turbo `connectedCallback` + React effects that only fire once the **real server-rendered HTML** is parsed into the Lexbor document and its custom elements upgraded/connected — the open entry-point/page-DOM cycle (parse real page HTML with Lexbor — the spec parser — then drive `connectedCallback`; not a stub snapshot).
- **Source positions / focused view**: every `@H`/`@S` carries the bundle call chain from `Error().stack` (QuickJS emits `at fn (file:line:col)` — zero engine patch). `callSite.loc` (click-through) and `focusedView` (endpoint+sink spans with gate-evidence = the example-value spread that proves a forced gate) are execution-grounded — the replacement for the dropped Babel viewer index.
- **Page-origin attribution**: unchanged — `background.js` resolves a relative recorded URL against the PAGE origin, not the script host.
- **Learning pipeline / protocol**: unchanged — `ast-thread.js` emits `fetchCallSites`; `background.js` feeds them through the same learning path as real traffic and does protocol classification. The engine does not classify protocols.
