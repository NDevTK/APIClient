- **Cross-session resume is REPLAY, not live-graph serialization.** A parked flow has TWO representations: HOT = the live heap frame in RAM (`JS_FlowResume` on the async heap-frame substrate — cheap suspend/resume for interleaving); COLD = a compact REPLAY RECIPE persisted to IDB = (bundle-ref/hash + the flow's DECISION VECTOR + the origin's one-per-endpoint `fromReply` cache + accumulated value). Eviction drops the live frame, keeps the recipe; rehydration RECONSTRUCTS the flow by re-running boot to the baseline then REPLAYING the decision vector — never by deserializing a live continuation + reachable object graph. **COW isolation is exactly what makes this sound: a flow's state is a deterministic function of (post-boot baseline, its OWN decision vector, its own execution) and NEVER of another flow's writes, so replaying its decisions over a re-run boot reconstructs it byte-for-byte — shared state and interprocedural effects included, because re-running boot re-establishes ALL of them natively.** Literal graph serialization is the WRONG primitive: it must rebuild object identity/aliasing across shared mutable state (the exact case that breaks it), and quickjs has no continuation serializer; replay sidesteps both. Replay cost is bounded by the eviction policy — only SHALLOW, low-value, few-decision flows are ever evicted (BFS keeps the deep productive ones hot), so a rehydrated flow is always cheap to replay. The decision vector IS the serialized continuation, compact and robust. **A recipe self-identifies by FUNCTION SOURCE (`JS_OrphanHash` = FNV-1a over the orphan's `b->source`), NOT by a positional collection index — collision-free + position-independent, so on resume it locates THE SAME FUNCTION by what it IS, in ANY context (present → drive with its decision vector; absent/different-source → skip; NEVER the wrong function). Shared state is re-established per document by re-running its OWN boot before replay; the same script in a different context is a different flow only because its baseline differs, and re-running that document's boot establishes exactly that. A positional index (or a filename+line+col hash) is the WRONG identity: script order / definition site shifts across contexts, silently pointing the recipe at a different function — the exact bug source-identity removes.**
- **Prioritization, never fixpoint termination.** Nothing terminates; the unproductive is starved to ~0 CPU, resumable. An overflow-prone forced recursion is usually an ARTIFACT — forced/opaque branches drive a continue-arm into a call stack real input could never reach; the opcodes see it soundly (`OP_if` on an OPAQUE value driving `OP_call`), the sound replacement for `recur_collapse`.

There is NO privileged post-boot baseline and NO single serial undo-log; the common boot(opaque) prefix is merely a CACHED checkpoint delta the opaque flows share, and cross-session resume re-runs boot then replays the decision vector over this same baseline. Persisted to IDB, this is what makes the frontier UNBOUNDED and resumable across browser restarts.
