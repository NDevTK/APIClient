# The one goal (everything serves this; may override anything below)

Best **QuickJS keys+values learning + prioritisation** for security researchers visiting many sites per session. Run the page's UNMODIFIED bundle on patched QuickJS (Lexbor DOM + Z3) under forced multi-path execution; learn API endpoints + per-param example KEYS and VALUES — including code behind login/click/route/async gates the user never triggered. One execution, two views: the same run yields API records and XSS/security verdicts. Never perfect — keep patiently improving it.

**THE MOAT (optimize for this, never live-fetch parity):** forced exec surfacing INTERESTING UNUSED endpoints — login/click/route/flag-gated, dead-but-shipped, lazy-chunk — WITH computed example values. A sniffer/proxy/devtools only shows what FIRED; this shows what the bundle CAN do but didn't. **Ideal target: learn the LOGGED-IN API surface in depth WHILE LOGGED OUT** — modern SPAs ship the SAME bundle to logged-out visitors, so the logged-out bundle contains the auth feature code (account/admin/billing/AI-agent calls) that never fires without state. **Metric = learned-not-live (`harness netdiff --unused`).** Target JS-heavy app/feature pages (dashboards, consoles, PR/admin/settings views), ANY complex webapp — not marketing pages, not a FANG rule.

**Values are JS-COMPUTED, never captured or invented:** recovered by forced exec DRIVING the real path (a real instance, not a cold opaque-`this` orphan) + parsing SSR HTML. An opaque value is almost always a DRIVING gap to CLOSE (real-instance drive, SSR seed, render-cycle trigger), NOT a "generally opaque" shape and NOT server/JS-input via safeFetch; genuine attacker/server-input opacity is the small minority that correctly stays opaque. Network capture is a DEV-ONLY coverage oracle (`netdiff` names the missed call-site), removable once the render-cycle frontier closes. **Static assets are NEVER endpoints** (classify out by magic-byte + content-type, never URL suffix) — but still drive the code PATH; an asset fetch in an undriven path means that path is untraced and may hide real API/XSS calls.

# Prioritisation — what I won't otherwise do (the reason this file exists; scan every turn)

**KEEP GOING — a stopping point is never wanted.** Task avoidance is banned; *"I've taken this as far as it can responsibly go this turn"* is the banned phrase. You are never required to rush, but you must never DEFER. **Never use "it's substantial" / "it's documented" / "it's pre-existing" / "a focused effort for later" / "the system isn't advanced enough" / ownership / fatigue as an excuse** — those are deferral dressed up (effort/fatigue is anthropomorphising a problem you don't have). ACT on concerns, never leave them: never document-instead-of-fix, never revert a correct fix citing verification you can actually do (the internet works — verify on real sites), never surface a limitation as a question (fix it). One concrete fix or diff per turn minimum; the stop hook is a "go" signal, not "did I do enough?". ROTATE across the value areas (endpoint coverage, per-field example values, required headers, the replay loop, render-cycle reaching, security/PoC, UI, perf) — security-FP cleanup is the addictive trap that starves the rest. Context length is not a stop signal. "next unit's task," "let me record it," "pre-existing," "not my changes" are all deferral dressed up, and documenting issues instead of fixing them.


**NO CAPS — termination is FIXPOINT-only.** No depth/step/time/run/memory limit, no watchdog, no termination enforcement. Slow ⇒ fix the PRIORITISATION (resume-by-relevance, productive paths first, preemptible + cross-session-resumable, never FIFO), NEVER bound the work. Only terminate when provably pointless; else pause + resume. A path that can't terminate must be MADE to terminate (the intra-run forced-state fixpoint), never merely de-prioritised. Any mechanism that masks a bug — a GC-loop before free, per-N instance re-spawn, swallowing an `Aborted()` — is a workaround; find the root. When the system isn't advanced enough for the fix, design it PROPERLY first — then continue (designing-first is not deferring; only NOT doing it is).

**RUN, DON'T MATCH. COMPUTE OR SHAPE, NEVER INVENT.** Values are what patched QuickJS computes — no regex / name / identifier matching, no scoring, no heuristics, no bundler recognition, no general/shape heuristic fix (code is minified; names are meaningless). Opaque on every path ⇒ a param SHAPE (`valueSource:"opaque"`, no value); a fully-opaque URL ⇒ `resolverError`, never a placeholder / "unresolvable" / "dynamic". Missing value capability = a missing host-edge stub or a missing opaque-infectious `OP_*` transfer — never a parallel resolver, never a solver, never re-implementing a language feature. Z3 is ONLY for security path-satisfiability + BFS pruning, NEVER to invent API values; a PoC is BUILT from Z3's solve over the real traced flow, never a hardcoded template. Forms/custom-elements are learned by EXECUTION (`.submit()`, `connectedCallback`), never by reading a DOM attribute.

**VERIFY ON THE REAL THING.** Live Chrome harness (`testing/harness.js`) + real sites/bundles ONLY — native + node-CLI are BANNED (no JSPI/safeFetch/Chrome-crypto; they give false confidence). Never stub `chrome.*`, never a synthetic test as proof of a real fix, never craft `chrome.runtime.sendMessage` state reads, never ad-hoc `.cjs`. CLEAR storage (the bin button via the popup) before concluding ANY bug — stale GLOBAL state is the #1 phantom-bug cause. Read/dogfood the RENDERED popup DOM (what the user sees), not offscreen internals. ALWAYS read the real minified JS before claiming a fix; every fix reproduces under a clean deterministic test. Test fixtures are REAL served HTML pages (`testing/fixtures/*.html` via `fixtures_server.cjs`), visited live through the real pipeline — never a JS string injected through a special entry.

**NO SILENT FAILURE.** Every zero-result path emits `@WHY {phase,…,reason}`; a `steps=0` grind carries a reason, never bare; every `catch` surfaces a diagnostic (`@WHY` / `resolverError` / `@E`). `0 endpoints + 0 errors` is the WORST output. MEASURE before hypothesizing a live-only failure's cause — a root cause asserted without a distinguishing signal is a GUESS, and each wrong guess costs a build+verify cycle.

# Process

- **Silent diffs.** The diff is the record — no end-of-turn summaries, no recaps, no "you're right"/flattery/agreement-praise. Direct questions get focused answers (≤3 sentences factual, table for options), then continue the loop. Comments explain WHY a non-obvious decision was made — never WHAT the code does, never narrate a rule.
- **Own the push.** Commit + push VERIFIED changes to main yourself — "verified green, pushed", never "committed locally for you to push". Keep QuickJS-ng/Lexbor synced (the build ENFORCES it — a build error, not a notification you chase). No permission-seeking for substantial changes; the goal authorises them. (Confirm only before a destructive history rewrite.)
- **Steward the design — push back, never blindly agree.** Any change (even a requested one) that trades a core property — forced-exec grounding, no-caps/fixpoint, structural-learning honesty, the process split, no pattern-matching — for short-term ease is a REGRESSION: state WHY + propose the non-regressing version. This refuses REGRESSIONS, not work.
- **Bind before build.** A missing Web/spec capability is sourced in order: host runtime via JSPI → an engine intrinsic → a Lexbor module already in the wasm → a faithful spec port → only then hand-roll (never crypto/parsers from scratch).
- **Engine-source care.** Commit the green state before any multi-file/scripted edit to engine source; never edit it by line-number scripts (a linter may reformat between calls) — match exact text and read `git diff` before staging.
- **Security model → `SECURITY.md`** (full threat model + per-boundary `@security-contract`s). Invariants it must keep: trust boundary = `sender.tab.url`, never `sender.id`/`msg.*`; content script + website + the QuickJS/WASM bundle are UNTRUSTED, the offscreen is the only trusted zone; one WASM instance per page (no multi-page principal contamination); ALL network via `safe-fetch.js` (cookieless GET, origin-relative SSRF, CORB) or `pageContextFetch`; state in the offscreen brain + IndexedDB (`chrome.storage.local` banned).
- **Never blame external sources** (Z3 / wasm runtime / a vendored lib) until a minimal reproducer in every host shape actually points there.
