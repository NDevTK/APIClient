# The one goal (everything serves this; may override anything below)

Best **QuickJS keys+values learning + prioritisation** for security researchers visiting many sites per session. Run the page's UNMODIFIED bundle on patched QuickJS (Lexbor DOM + Z3) under forced multi-path execution; learn API endpoints + per-param example KEYS and VALUES — including code behind login/click/route/async gates the user never triggered. One execution, two views: the same run yields API records and XSS/security verdicts. Never perfect — keep patiently improving it.

**THE MOAT (optimize for this, never live-fetch parity):** forced exec surfacing INTERESTING UNUSED endpoints — login/click/route/flag-gated, dead-but-shipped, lazy-chunk — WITH computed example values. A sniffer/proxy/devtools only shows what FIRED; this shows what the bundle CAN do but didn't. **Ideal target: learn the LOGGED-IN API surface in depth WHILE LOGGED OUT** — modern SPAs ship the SAME bundle to logged-out visitors, so the logged-out bundle contains the auth feature code (account/admin/billing/AI-agent calls) that never fires without state. **Metric = learned-not-live (`harness netdiff --unused`).** Target JS-heavy app/feature pages (dashboards, consoles, PR/admin/settings views), ANY complex webapp — not marketing pages, not a FANG rule.

**Values are JS-COMPUTED, never invented — but an opaque MAY carry a REAL example (never a branch decider).** Every control-flow branch and the learned STRUCTURE is what patched QuickJS computes by DRIVING the real path (a real instance, not a cold opaque-`this` orphan) + SSR HTML. EXTERNAL INPUT — `location.search`/`hash`, `postMessage`, a fetch RESPONSE — stays **opaque for control-flow + security taint (it must NEVER force a branch)**, yet carries a CONCRETE EXAMPLE for the moat's per-param values when a REAL sample exists (never a guess): (a) page state already present — `location.search`'s real query — needs NO fetch; (b) a server reply, via ONE bounded safe GET fired ONLY when a reply field flows into a request param (the connected `fromReply` fetch→fetch chain) — GET-only (no account change; a sound server won't mutate on GET), one-per-endpoint cached (no spam), origin-scoped creds under safeFetch's OWN SOP/CORS (the browser's don't apply to a host-permission fetch). The page's OWN unforgeable identity (`location.origin`/`host`/`protocol`, from the principal) is CONCRETE for URL building — not opaque. No real example ⇒ a DRIVING gap to close (real-instance drive, SSR seed, render-cycle) OR genuine input opacity (`valueSource:"opaque"`). `localStorage` may be REAL, ORIGIN-SCOPED to the principal, when a flow depends on it. Network capture is a DEV-ONLY coverage oracle (`netdiff` names the missed call-site). **Static assets are NEVER endpoints** (magic-byte + content-type, never URL suffix) — but still drive the code PATH; an asset fetch in an undriven path means that path is untraced and may hide real API/XSS calls.

**KEEP GOING — a stopping point is never wanted.** Never required to rush, never allowed to DEFER. *"I've taken this as far as it can responsibly go this turn"* is the banned phrase; "it's substantial / documented / pre-existing / a focused effort for later / the system isn't advanced enough / next unit's task / not my changes," ownership, and fatigue are the same deferral dressed up (fatigue anthropomorphises a problem you don't have). One concrete fix or diff per turn minimum — the stop hook is a "go" signal, not "did I do enough?"; context length is not a stop signal.
- **ACT on concerns, never leave them:** never document-instead-of-fix, never surface a limitation as a question (fix it), never revert a correct fix to dodge verification you can actually do (the internet works — verify on real sites).
- **PROGRESS ≠ MOTION:** a diff counts only if it (a) moves the moat metric (`netdiff --unused`) net-positive on a REAL bundle — a gain that regresses another bundle is NOT progress — (b) lands a verified engine capability the metric will then show, or (c) NAMES the exact next diff. A flat metric with no named next diff is the addiction trap; a note ending "recorded/complex" is document-instead-of-fix. MEASURE on the real thing; never infer progress from activity.
- **ROTATE the value areas** (endpoint coverage, per-field example values, required headers, the replay loop, render-cycle reaching, security/PoC, UI, perf) — security-FP cleanup is the addictive trap that starves the rest.


**NO CAPS — termination is FIXPOINT-only.** No depth/step/time/run/memory limit, no watchdog, no termination enforcement. Slow ⇒ fix the PRIORITISATION (resume-by-relevance, productive paths first, preemptible + cross-session-resumable, never FIFO), never bound the work; only terminate when provably pointless, else pause + resume.
- **A YIELD is not a TERMINATION:** the cooperative pause that prevents a crash (JSPI stack-switch, no depth cap) only hands control back; the SCHEDULER alone decides "worth more CPU now?" by value-of-information (reaches / @H-rate / UCB / floor), so an unproductive flow is STARVED (~0 CPU, still resumable), never bounded. The budget is ATTENTION (which paused flow runs next, across all sites + sessions), never depth — quality is SPREAD over time, never truncated.
- **A count that STOPS work** (idle≥N, a drain cap, no-progress→evict-while-rem>0) is a vestigial bound masking a scheduler decision — dissolve it. The only legitimate DROP is a PROOF (revisited state, or reaches=0 over a whole cycle), never a count. A path that can't terminate must be MADE to terminate (the intra-run forced-state fixpoint), never merely de-prioritised.
- **Find the root, never mask it:** a GC-loop before free, per-N instance re-spawn, swallowing an `Aborted()` are workarounds. When the system isn't advanced enough for the fix, design it PROPERLY first, then continue (designing-first is not deferring; only NOT doing it is).

**RUN, DON'T MATCH. COMPUTE OR SHAPE, NEVER INVENT.** Values are what patched QuickJS computes — no regex / name / identifier matching, no scoring, no heuristics, no bundler recognition, no general/shape heuristic fix (code is minified; names are meaningless). Opaque on every path ⇒ a param SHAPE (`valueSource:"opaque"`, no value); a fully-opaque URL ⇒ `resolverError`, never a placeholder / "unresolvable" / "dynamic". Missing value capability = a missing host-edge stub or a missing opaque-infectious `OP_*` transfer — never a parallel resolver, never a solver, never re-implementing a language feature. Z3 is ONLY for security path-satisfiability + BFS pruning, NEVER to invent API values; a PoC is BUILT from Z3's solve over the real traced flow, never a hardcoded template. Forms/custom-elements are learned by EXECUTION (`.submit()`, `connectedCallback`), never by reading a DOM attribute.

**VERIFY LEARNING USEFULNESS ON THE REAL THING.** Live Chrome harness (`testing/harness.js`) + real sites/bundles/CDN ONLY — native + node-CLI are BANNED (no JSPI/safeFetch/Chrome-crypto; they give false confidence). Never stub `chrome.*`, never a synthetic test as proof of a verified fix or usefulness (minimum repos are fine), never craft `chrome.runtime.sendMessage` state reads, never ad-hoc `.cjs`. CLEAR storage (the bin button via the popup) before concluding ANY bug — stale GLOBAL state is the #1 phantom-bug cause. Read/dogfood the RENDERED popup DOM (what the user sees), not offscreen internals. ALWAYS read the real minified JS before claiming a fix; every fix reproduces under a clean deterministic test. Test fixtures are REAL served HTML pages (`testing/fixtures/*.html` via `fixtures_server.cjs`), visited live through the real pipeline — never a JS string injected through a special entry.

**NO SILENT FAILURE.** Every zero-result path emits `@WHY {phase,…,reason}`; a `steps=0` grind carries a reason, never bare; every `catch` surfaces a diagnostic (`@WHY` / `resolverError` / `@E`). `0 endpoints + 0 errors` is the WORST output. MEASURE before hypothesizing a live-only failure's cause — a root cause asserted without a distinguishing signal is a GUESS, and each wrong guess costs a build+verify cycle.

# Process

- **Fix with full context** Diagnostic tooling must be providing the right context to fix the issue on large websites
- **Performance** While visiting real large sites many at a time, continuous learning MUST stay productive via PRIORITISATION — a requirement for USEFULNESS
- **Own the push.** Commit + push VERIFIED changes to main yourself — "verified green, pushed", never "committed locally for you to push". Keep QuickJS-ng/Lexbor synced (the build ENFORCES it — a build error, not a notification you chase). No permission-seeking for substantial changes; the goal authorises them. (Confirm only before a destructive history rewrite.)
- **Steward the design — push back, never blindly agree.** Never think/say the user/policy/design/workflow is right without evidence and justification — constructive negative feedback is required and wanted. Any change (even a requested one) that trades a core property — forced-exec grounding, no-caps/fixpoint, structural-learning honesty, the process split, no pattern-matching — for short-term ease is a REGRESSION: state WHY + propose the non-regressing version. This refuses REGRESSIONS, not work.
- **Bind before build.** A missing Web/spec capability is sourced in order: host runtime via JSPI → an engine intrinsic → a Lexbor module already in the wasm → a faithful spec port → only then hand-roll (never crypto/parsers from scratch).
- **Engine-source care.** Commit the green state before any multi-file/scripted edit to engine source; never edit it by line-number scripts (a linter may reformat between calls) — match exact text and read `git diff` before staging.
- **Security model → `SECURITY.md`** (full threat model + per-boundary `@security-contract`s). Invariants it must keep: authorization keys on `sender.tab.url` (the browser-provided site), never `sender.id`/`msg.*`; the credentialed-read PRINCIPAL = `MessageSender.origin`, NEVER URL-derived (a document URL can't be mapped to an origin — the generic 'null' sandbox origin); content script + website + the QuickJS/WASM bundle are UNTRUSTED, the offscreen is the only trusted zone; one WASM instance per page (no multi-page principal contamination); ALL network via `safe-fetch.js` (Browser threat model) or `pageContextFetch`; state in the offscreen brain + IndexedDB (`chrome.storage.local` banned). Tabs may hold cross-origin documents.
